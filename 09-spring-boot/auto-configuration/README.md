# Auto Configuration

## Description

This example demonstrates how Spring Boot automatically configures application infrastructure based on the dependencies available on the classpath.

The example uses Spring Boot's JDBC starter together with an embedded H2 database. We use `JdbcTemplate` in the application without defining a `JdbcTemplate` bean ourselves.

This demonstrates one of the key ideas behind Spring Boot:

> Spring Boot can automatically configure commonly used infrastructure when the required dependencies and conditions are present.

---

## Learning Objectives

- Understand what Spring Boot auto-configuration is.
- Learn how `@EnableAutoConfiguration` participates in application startup.
- Understand how `@SpringBootApplication` enables auto-configuration.
- Learn how Spring Boot uses classpath dependencies to determine what to configure.
- Understand how `spring-boot-starter-jdbc` enables JDBC auto-configuration.
- Understand how `JdbcTemplate` can be provided automatically.
- Learn the difference between using `spring-jdbc` directly and using `spring-boot-starter-jdbc`.
- Understand that auto-configuration does not mean that Spring Boot configures everything unconditionally.
- Understand that application-defined beans can influence or replace auto-configured beans.

## Dependencies

The example uses Spring Boot's JDBC starter:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>
</dependency>
```

An embedded H2 database is used for the example:

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```

### Why `spring-boot-starter-jdbc`?

We could add Spring's JDBC module directly:

```xml
<dependency>
    <groupId>org.springframework</groupId>
    <artifactId>spring-jdbc</artifactId>
</dependency>
```

That would provide APIs such as `JdbcTemplate`.

However, this example is specifically about **Spring Boot auto-configuration**, so using the Boot starter is more appropriate.

The starter provides the JDBC functionality while also allowing Spring Boot's JDBC auto-configuration to configure the required infrastructure.

Conceptually:

```text
spring-boot-starter-jdbc
        │
        ├── Spring JDBC
        │      └── JdbcTemplate
        │
        └── JDBC infrastructure
                │
                └── Spring Boot auto-configuration
```

The application does not manually create the `JdbcTemplate`.

## Application

```java
@SpringBootApplication
public class Application {

    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

There is no explicit `DataSource` or `JdbcTemplate` configuration in the application.

The important part is:

```java
SpringApplication.run(Application.class, args);
```

When the application starts, Spring Boot performs its normal application startup process, including auto-configuration.

---

## How Auto Configuration Works

`@SpringBootApplication` includes `@EnableAutoConfiguration`.

Conceptually:

```text
@SpringBootApplication
        │
        ├── @Configuration
        │
        ├── @ComponentScan
        │
        └── @EnableAutoConfiguration
                    │
                    ↓
             Spring Boot examines
             the application
                    │
                    ├── Classpath
                    ├── Existing beans
                    └── Configuration
                    │
                    ↓
             Applies matching
             auto-configurations
```

For this example, Spring Boot sees the JDBC dependencies and H2 database driver and can configure the JDBC infrastructure required by the application.

## GreetingRepository

```java
@Repository
public class GreetingRepository {

    private final JdbcTemplate jdbcTemplate;

    public GreetingRepository(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }

    public void save(String greeting) {
        jdbcTemplate.update("INSERT INTO greetings (message) VALUES (?)", greeting);
    }

    public int count() {
        return jdbcTemplate.queryForObject("SELECT COUNT(*) FROM greetings", Integer.class);
    }
}
```

The repository depends on `JdbcTemplate`:

```java
public GreetingRepository(JdbcTemplate jdbcTemplate)
```

But we never define:

```java
@Bean
JdbcTemplate jdbcTemplate() {
    // implementations
}
```

Spring Boot provides the `JdbcTemplate` automatically.

This is the main behavior demonstrated by this example.

## Database Schema

The example uses an embedded H2 database.

`schema.sql` contains:

```sql
CREATE TABLE greetings (id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    message VARCHAR(255) NOT NULL
);
```

Spring Boot detects the embedded database and initializes the database using the SQL schema.

## What We Configured vs What Spring Boot Configured

The example intentionally has very little configuration.

### We provide

```text
spring-boot-starter-jdbc
H2
GreetingRepository
schema.sql
```

### Spring Boot provides

```text
DataSource
    ↓
JdbcTemplate
    ↓
available for dependency injection
```

The important distinction is that the application **uses** `JdbcTemplate` but does not **create** it.

---

## Auto Configuration vs Manual Configuration

Without Spring Boot auto-configuration, we could manually configure a data source and `JdbcTemplate`:

```java
@Bean
DataSource dataSource() {
    // Configure the database connection.
}

@Bean
JdbcTemplate jdbcTemplate(DataSource dataSource) {
    return new JdbcTemplate(dataSource);
}
```

With Spring Boot, this configuration can be supplied automatically when the required conditions are satisfied.

Instead, our repository simply declares its dependency:

```java
public GreetingRepository(JdbcTemplate jdbcTemplate) {
    this.jdbcTemplate = jdbcTemplate;
}
```

Spring Boot takes care of providing the infrastructure.

---

## Auto Configuration Is Conditional

Spring Boot does not simply configure every possible feature.

Auto-configuration is generally based on conditions such as:

- Which classes are available on the classpath.
- Which dependencies are present.
- Whether certain beans already exist.
- Application configuration.
- Other auto-configuration conditions.

For example, this example has:

```text
spring-boot-starter-jdbc
        +
H2
        ↓
JDBC-related auto-configuration
        ↓
DataSource
        ↓
JdbcTemplate
```

If the required dependencies are not present, the corresponding auto-configuration may not be activated.

---

## Existing Beans Can Affect Auto Configuration

Auto-configuration is designed to work with application-defined configuration.

For example, if an application defines its own infrastructure bean, Spring Boot may back away from creating a conflicting auto-configured bean when the relevant auto-configuration is conditional on that bean being absent.

This allows developers to use Spring Boot's defaults while still being able to customize the application when necessary.

## A Useful Experiment

To understand the role of the starter dependency, temporarily remove:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>
</dependency>
```

The application will no longer have the JDBC infrastructure required by `GreetingRepository`.

You can also experiment with defining your own `JdbcTemplate` bean and observe how application-defined configuration can affect auto-configuration.

These experiments help demonstrate that auto-configuration is not magic. Spring Boot evaluates the application's environment and applies configuration based on a set of conditions.


You can also run `Application.main()` directly from your IDE.

---

## Key Takeaways

- Spring Boot provides automatic configuration for many common application features.
- `@SpringBootApplication` enables auto-configuration through `@EnableAutoConfiguration`.
- Auto-configuration considers the application's classpath and existing configuration.
- `spring-boot-starter-jdbc` provides the dependencies needed for JDBC support.
- `JdbcTemplate` comes from Spring JDBC but can be automatically configured by Spring Boot.
- The application does not need to define its own `JdbcTemplate` bean for this example.
- Auto-configuration is conditional rather than unconditional.
- Developers can still provide their own configuration when Spring Boot's defaults are not appropriate.
